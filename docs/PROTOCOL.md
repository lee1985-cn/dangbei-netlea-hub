## 1. GATT 服务与特征

服务 UUID（`indexOf("FFF0")` 匹配）：

```
0003CBBB-0000-1000-8000-00805F9BFFF0
```

特征值（128 位，厂商自定义，注意不是标准 FFE0）：

| 用途 | UUID | 说明 |
|---|---|---|
| 控制写入 `writeCtl` | `0003CBBB-0000-1000-8000-00805F9BEEE1` | 开关/档位/喂食 |
| 行程写入 `writeTrip` | `0003CBBB-0000-1000-8000-00805F9BEEE2` | 106 字节行程表 |
| 间隔/其他 `writeInterval` | `0003CBBB-0000-1000-8000-00805F9BDDD3` | 气泵用 |
| **状态通知 `notify`** | `0003CBBB-0000-1000-8000-00805F9BEEE4` | 需 `notifyBLECharacteristicValueChange` |
| 语音 `voice` | `0003CBBB-0000-1000-8000-00805F9BEEE5` | 切回蓝牙控制也走这条 |
| OTA 服务 | `...FE11`，特征 `2C00`/`2C01` | 固件升级，暂不用 |

小程序还会按 `EEE1/FFE1/DDD1`、`DDD3`、`EEE4/FFE4/DDD4` 等做**后缀模糊匹配**，说明同一套代码兼容多个 OEM 模组。写入统一用 `writeType: "writeNoResponse"`。

## 2. 帧格式（校验 + XOR 混淆）

```python
KEY = [76,101,100,115,38,70,117,110]   # ASCII "Leds&Fun"

def crc(data):            # 自定义 8 位移位 XOR 校验
    n = 0
    for b in data:
        r = b
        for k in KEY:
            if r & 1: n ^= k
            r = (r >> 1) & 0xFF
    return n & 0xFF

def encode(data):         # 发送
    t = crc(data)
    return bytes([t] + [t ^ b for b in data])

def decode(frame):        # 接收
    t = frame[0]
    data = bytes([t ^ b for b in frame[1:]])
    assert crc(data) == t   # 校验失败即丢包
    return data
```

即：**首字节是校验值，其余每字节 = 校验值 XOR 明文**。

## 3. 控制命令 `pumpControlCMD`

明文 12 字节，编码后 13 字节发送到 `EEE1`：

```
[0] = 0x02        固定：水泵类命令
[1] = onOff       1=开 0=关
[2] = 0           （小程序里恒为 false）
[3] = 0x01
[4] = 0x01
[5] = model       工作模式
[6] = gear        档位（1号桶 1~20）
[7] = level       流量等级（mode=2 时用，否则 0）
[8] = timing      喂食分钟数（mode=3 时用，否则 0）
[9] = 0
[10..11] = 0x58 0x02   固定尾（88, 2）
```

`model` 取值：

| model | 含义 |
|---|---|
| 1 | 纯档位模式 |
| 2 | 档位 + level |
| 3 | 喂食模式（用 timing = 分钟） |
| 6 | 关机时强制使用 |

**注意**：`onOff == 0` 时 model 被强制改成 6。

| 动作 | 明文 | 发送帧 |
|---|---|---|

| 切回蓝牙控制 | `02 04` | `01 03 05` |

## 4. 状态上报（`EEE4` 通知）

收到后先 `decode`，明文长度 < 8 则丢弃：

```
[1] = charge      电量
[2] = electric    电压/电流
[4] = gear        当前档位（0 = 停机）
[6] = workModel   工作模式：1=档位 2=档位+level 3=喂食设置 5=喂食中 6=关 7=自吸排气
[7] = errorCode   错误码
```

主动读状态：往 `EEE1` 写 `02 02`（帧 `00 02 02`）。

## 5. 重要行为约束

1. **自吸排气**（workModel=7）：开机后滤桶要先排气，30 秒 ~ 15 分钟，期间**拒绝蓝牙控制**。自动化里开机后不要立刻发档位，等状态变成 workModel=1 再发。
2. **实体按键模式**（controlType=0）：设备可能处于面板按键控制态，需要先写 `02 04` 切回蓝牙控制，否则命令不生效。
3. **单连接**：同一时刻只能有一个 BLE 主机连着。ESP32 占着连接时手机小程序连不上，反之亦然 → 必须"发完即断"。
4. **无配对**：不需要 bonding，直接连上就能读写。
5. 行程表（`EEE2`，106 字节）格式已解出但暂不使用——行程存在设备内，HA 只需切档/喂食/开关。

## 6. 与投影仪固件共存

- 投影仪用 `BleKeyboard`（NimBLE peripheral），滤桶用 GATT client（central），**角色不冲突**，C3 支持同时跑。
- 投影仪的唤醒包模式要 `ESP.restart()` 进 Mode A，**重启会断掉滤桶连接** → 唤醒后需要重新连滤桶（重连约 1~2 秒，可接受）。
- NVS 里 BleKeyboard 的 bonding 密钥不受影响。
